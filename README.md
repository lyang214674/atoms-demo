# Atoms Demo · 用一句话生成可运行的网页应用

- **在线体验**：https://atoms.aihunter.space （备用：https://atoms-demo.lyang214674.workers.dev）
- **源码**：https://github.com/lyang214674/atoms-demo
- **一句话**：输入需求 → Planner 拆解并等你确认 → Builder 流式写出单文件应用 → Reviewer 逐项验收 → 沙箱里立刻运行；可继续对话迭代、回看与恢复版本、查看与导出源码、公开分享、Remix。

---

## 一、项目概述

Atoms Demo 是一个**智能体驱动的网页应用生成工作台**。用户用自然语言描述想法，三个分工明确的智能体接力完成规划、构建与审查，产物是一份可独立运行的单文件 HTML 应用，在页面内的沙箱中实时预览。每一次生成都是一个不可变版本，支持对话式迭代、历史回看与恢复；完成的作品可以一键公开分享，访客无需登录即可运行，也可以 Remix 到自己账号继续创作。

设计围绕三个目标：

1. **让"智能体驱动"可见、可控**：规划结果结构化呈现并允许编辑，用户确认后才进入构建；构建过程逐字流式输出；审查结论逐项列出。每一步的输入输出都落库，可回放。
2. **让生成物真正可用**：不是截图或代码块，而是在隔离沙箱中运行的应用，带持久化、可导出、可分享、可被他人复用。
3. **在免费资源内稳定运行**：模型、数据库、托管全部使用 Cloudflare 免费额度，用配额、重试、超时与恢复机制保证评测期间不失败、不失控。

### 核心能力

- **账号体系**：邮箱密码自助注册与登录，HttpOnly 会话，登录与注册按 IP 限频防爆破
- **需求分流**：提问、空泛描述在进入模型前被拦下并给出引导，不消耗额度、不产生空项目
- **三智能体流水线**：Planner 产出功能 / 页面 / 数据模型 / 风格的结构化计划（可编辑、需确认）→ Builder 流式生成完整 HTML → Reviewer 静态检查 + 模型对照计划逐项验收，给出 pass / warn
- **实时执行记录**：三角色时间线、逐 token 输出、每步 start / done / error 事件落库，刷新可恢复
- **工作台**：左侧需求、版本、计划、审查与迭代输入；右侧预览 / 代码双视图。预览支持桌面 / 手机宽度、刷新、清空应用数据、新标签打开；代码视图带行号，可复制、可下载为独立 `.html`
- **版本管理**：每次迭代生成新版本；任意历史版本可切换查看，可一键"恢复为最新"（不调用模型）；失败版本可重新规划或重新构建
- **应用内数据持久化**：生成的应用照常使用 `localStorage`，由注入的存储垫片在沙箱内接管并同步到工作台，刷新不丢
- **分享与再创作**：公开分享页 `/s/<slug>`，访客直接运行；一键 Remix 到自己账号；首页作品墙展示公开项目
- **稳定与成本护栏**：每用户每日 10 次 + 全站每日 30 次的原子配额（失败自动退回）、429/503 退避重试、审查超时不阻塞产物、中断的构建自动恢复为可重试、请求 Origin 校验与体积上限

## 二、三分钟评测指引

1. 打开 https://atoms.aihunter.space ，输入需求或点一个示例，例：`做一个番茄钟，可以设置专注时长，记录今天完成了几个番茄`
2. 用任意邮箱 + 6 位以上密码**自助注册**（无验证码、不发邮件）
3. 进入工作台，**Planner** 自动拆解需求（约 15s）。计划可以直接改，改完点「确认计划，开始构建」
4. **Builder** 流式输出代码（约 60–90s，左侧可见实时字符流），完成后右侧沙箱立刻运行；**Reviewer** 随后给出逐项检查结论
5. 切到右上「代码」标签查看带行号的源码，可复制或下载 `.html` 在本地直接打开
6. 在底部输入框继续说「加一个深色模式」→ 生成 v2；点左侧 v1 可回看，并可「恢复 v1 为最新」
7. 点「分享」→ 得到公开链接；换一个浏览器或账号打开，可直接运行，也可「Remix」到自己账号继续改；首页作品墙会出现这个项目

> 额度说明：线上模型使用 Cloudflare Workers AI 免费档。每账号每天 10 次生成、全站每天 30 次；失败不扣次数。遇到「今日额度已用完」请次日再试，或按第七节自行部署（十分钟内可完成）。

## 三、实现思路

### 3.1 整体架构

```
Browser  React 19 + Vite + Tailwind（SPA）
   │  fetch / SSE
Cloudflare Worker  Hono
   ├─ /api/auth/*                 注册 / 登录 / 会话（PBKDF2 + HttpOnly Cookie，按 IP 限频）
   ├─ /api/projects/*             项目、版本、迭代、恢复、分享
   ├─ /api/versions/:id/plan      Planner                （SSE，逐 token）
   ├─ /api/versions/:id/build     Builder + Reviewer     （SSE，逐 token）
   ├─ /api/share/:slug  /api/remix/:slug  /api/gallery    公开能力
   ├─ /raw/*                      生成物原始 HTML（CSP sandbox，注入存储垫片）
   └─ 其余路径 → 静态资源（SPA fallback）
D1 (SQLite)   users / sessions / auth_attempts / projects / versions / agent_events / usage_daily
Workers AI    @cf/google/gemma-4-26b-a4b-it（可切换任意 OpenAI 兼容接口）
```

前后端同仓库、一条 `wrangler deploy` 上线；自定义域名由 Cloudflare 在部署时自动配置 DNS 与证书。

### 3.2 三智能体流水线

三个角色是三次带不同系统提示词的独立模型调用，共享同一份结构化「计划」作为上下文：

| 角色 | 输入 | 输出 | 设计要点 |
|---|---|---|---|
| **Planner** | 用户需求（迭代时附上一版计划与修改意见） | `app_name / summary / features / sections / data_model / style` JSON | temperature 0.3；结果渲染为可编辑卡片，**用户确认后才进入构建**，避免理解偏差后白跑一次昂贵的生成 |
| **Builder** | 确认后的计划（迭代时附上一版 HTML） | 完整单文件 HTML | temperature 0.4；约束为 Tailwind CDN + 原生 JS + `localStorage`；文件体积有硬预算，防止长输出被截断；迭代是"基于上一版修改"而非重写 |
| **Reviewer** | 计划 + HTML | `verdict / checks[] / notes` | 先做确定性**静态检查**（文档完整、含脚本、有持久化、外部脚本白名单），再让模型对照计划逐条验收功能覆盖、空态、响应式；模型审查有 30s 超时，失败不影响产物 |

所有 token 经 Worker 直接转发给浏览器；计划、HTML、审查结论、每步事件全部写入 D1。刷新页面后从库中恢复状态，`agent_events` 可回放执行过程。

### 3.3 需求分流

进入 Planner 之前有一道零成本的规则分流：以「什么是 / 为什么 / 怎么」开头或以问号结尾的输入判为提问，「做一个应用」「帮我写个网站」这类没有具体操作的输入判为空泛。两者都不创建项目、不调用模型，而是返回一句带示例的引导。这样评测人随手输入的问句不会变成一个失败的项目，也不会消耗额度。

### 3.4 生成物的安全运行与持久化

生成的 HTML 是不可信代码。预览使用 `iframe sandbox="allow-scripts allow-forms allow-modals allow-popups"`（**不给** `allow-same-origin`），`/raw/*` 响应再加 `Content-Security-Policy: sandbox`。因此生成物拿不到访问者的 Cookie，也不能以站点身份调用我们的 API。

代价是：不透明源下浏览器禁止 `localStorage`，而应用几乎都靠它持久化。解决方式是在生成物 `<head>` 顶部注入一段存储垫片（`shared/storageShim.ts`）：原生存储不可用时切到内存实现，并通过 `postMessage` 把每次变更同步给工作台，工作台按项目存进自己的 `localStorage`，下次加载时回灌。这样既守住隔离边界，也保住"刷新不丢数据"；预览栏提供「清空数据」以便重测。

### 3.5 稳定性与成本

- **原子配额**：一条 `INSERT … SELECT … ON CONFLICT` 同时检查每用户与全站上限并预留名额，避免读后写在并发下超发；构建失败自动退回
- **重试与超时**：模型 429 / 503 / 500 按 1.5s / 4s / 8s 退避重试三次；Reviewer 30s 超时后保留静态检查结论；Builder 一完成即落库并标记可用，审查阶段的任何问题都不会让版本卡在"构建中"
- **中断恢复**：加载项目时，超过 4 分钟没有任何智能体事件的"构建中"版本自动转为"失败"，用户可一键重试
- **请求防护**：状态变更请求校验 Origin；请求体上限 200 KB；登录 / 注册每 IP 15 分钟 10 次
- **模型可替换**：默认 Workers AI（无 Key、无地区限制、免费额度）；`LLM_PROVIDER=openai` 即可切到任意 OpenAI 兼容接口，Key 只存服务端 Secret

## 四、关键取舍

| 选择 | 放弃 | 原因 |
|---|---|---|
| 单文件 HTML 产物 | 多文件 React 工程 + 打包 | 8 小时内稳定跑通；无构建链即可预览、导出、分享；静态检查也简单。代价：不支持真正的多文件项目与依赖管理 |
| 三次真实模型调用 + 人工确认门 | 一次调用 + 规则化的步骤展示 | 规划可编辑、审查可解释，"智能体驱动"是真实发生而非界面文案。代价：一次生成耗时约 1.5 分钟、三倍额度 |
| Workers AI（Gemma 4 26B） | 商用模型 API | 与 Worker 同平台、无地区限制、无需 Key、免费额度足够评测。代价：生成较慢、代码风格偏保守；已预留一键切换通道 |
| Hono + React SPA | Next.js 全栈框架 | 一条命令部署、SSE 与 D1 绑定直接、冷启动 13ms。代价：无 SSR，首屏依赖 JS |
| 应用数据经垫片存于浏览器 | 同步到服务端数据库 | 实现成本低、无额外接口与存储；满足"刷新不丢"。代价：不跨设备 |
| 自动审查 + 分享即发布 | 人工核验门 + 发布锁 | 评测流程更短；审查结论仍逐项可见。代价：没有"发布后冻结"的状态 |
| Cookie + D1 会话 | KV | Workers 免费档 KV 每日仅 1000 次写 |
| PBKDF2（WebCrypto） | bcrypt | Workers 免费档单请求 10ms CPU |
| 邮箱密码自助注册 | 邮件验证码 / OAuth | 评测最顺畅；Worker 不方便发邮件 |
| 每日配额 + 全站上限 | 无限制 | 宁可让评测人看到明确的"今日额度用完"，也不要静默失败或额度失控 |

## 七、技术栈与运行

### 技术栈

- 前端：React 19、Vite 6、Tailwind CSS 4、react-router 7
- 服务端：Hono 4 on Cloudflare Workers，TypeScript
- 数据：Cloudflare D1（SQLite），原生 SQL 迁移
- 模型：Cloudflare Workers AI（默认）/ 任意 OpenAI 兼容接口
- 测试：`node:test` + `node:sqlite`（Node ≥ 22.5）

### 本地运行

```bash
npm install
npx wrangler login                              # 本地 dev 的 AI 绑定也会调用 Workers AI
npx wrangler d1 migrations apply atoms-demo --local
npm run build && npx wrangler dev               # http://localhost:8787
# 或前端热更新：另开终端 npm run dev（Vite 5173，API 代理到 8787）
```

### 部署（Cloudflare 免费档）

```bash
npx wrangler login
npx wrangler d1 create atoms-demo               # 把返回的 database_id 填进 wrangler.jsonc
npx wrangler d1 migrations apply atoms-demo --remote
npm run deploy                                  # 输出 workers.dev 地址；配置了 routes 则同时绑定自定义域名
```

- 自定义域名：在 `wrangler.jsonc` 的 `routes` 中填写 `{"pattern": "your.domain", "custom_domain": true}`，域名所在区域需在同一 Cloudflare 账号下，部署时自动创建 DNS 与证书
- 换模型：改 `LLM_MODEL`（Workers AI 目录中不带 `require_workers_paid` 的模型可在免费档使用）
- 换供应商：`LLM_PROVIDER=openai` + `LLM_BASE_URL` + `npx wrangler secret put LLM_API_KEY`，例如 DeepSeek `https://api.deepseek.com/v1` + `deepseek-chat`

### 验证

```bash
npm run check        # 类型检查 + 单元测试
npm test             # 仅单元测试
```

单元测试覆盖：需求分流规则、配额 SQL（每用户 / 全站上限、并发不超发）、登录限频窗口、Origin 校验、模型输出提取（围栏 / 前后缀 / 推理块）、静态检查、存储垫片注入（幂等、转义）。

## 八、安全与边界

- 生成物只能是单文件 HTML / CSS / JS，运行在不含 `allow-same-origin` 的沙箱中，外加 CSP sandbox；拿不到 Cookie，不能以站点身份发请求
- 外部脚本仅允许 Tailwind CDN 与 Google Fonts，其余会被 Reviewer 标记
- 所有项目、版本、分享、恢复接口校验账号归属；分享页与 Remix 只暴露已完成的版本
- 模型 Key 只存服务端 Secret；默认 Workers AI 路径无需任何 Key
- 配额限制的是本应用发出的调用次数，不等同于模型服务商的计费上限

## 九、开发过程与 AI 工具

全程在 Cursor 中与模型协作完成，约 8 小时：

1. 分析题目与产品形态，确定「单文件产物 + 三角色流水线 + Cloudflare 全家桶」，写出任务拆解与取舍表
2. 逐文件生成 Worker（路由、D1 访问层、鉴权、LLM 客户端、提示词）、Schema 与 React 页面
3. 脚本化冒烟测试 API（注册 / 重复注册 / 错误密码 / 未登录 / SSE 错误事件），再跑端到端生成
4. 上线后处理两类真实问题：模型地区限制（切换到 Workers AI）与沙箱下 `localStorage` 不可用（存储垫片），并用真实浏览器验证生成物可运行
5. 补齐工程细节：原子配额、登录限频、Origin 校验、审查超时、中断恢复、单元测试、代码视图、版本恢复、自定义域名

人工判断集中在：安全边界（sandbox、CSP、Secret）、免费额度约束（KV 写次数、CPU 时间、模型 neurons）、模型选型，以及评测流程的取舍。
